# Plan 12d: a footer that says what the app is doing. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add a one-line footer under the browser with three parts:
- the open list's facts;
- the latest message;
- one pill per background job, with done / total, a bar, the time left, and Pause / Resume / Stop.

**Architecture:**
- The session builds a `Vec<JobView>` each pass from the jobs' own non-blocking state and puts it in the frame. Analysis, covers, scan and stems are owned by library mode; import and export by the session.
- The window draws the footer from the frame.
- Pause, resume and stop are `UiCommand::Job` commands, which the session routes to the owning job.
- The top bar's status line moves to the footer.

**Tech Stack:** Rust, egui 0.37 and egui_kittest, plus the existing `library::jobs`, `CoverWorker`, `StemsControl` and `interop` export and import.

**Spec:** `docs/superpowers/specs/2026-11-14-12d-footer-design.md`, including "Decisions after the builder check".

**Branch:** `feat/plan-12d-footer`, cut from `main` after plan 12c merges.

## Global Constraints

- "The footer must never slow the audio or the window. It reads job state from the frame; no
  job waits on the window, and the window never waits on a job."
- "A stopped USB export must never leave a broken stick. A stopped import must never leave a
  half-applied playlist or hotcue set."
- "A paused background cover lookup must make no network request until it is resumed."
- "The footer must not take more than one text line from the browser."
- A pause does not survive a relaunch: jobs start again on their own at launch.
- Earlier constraints still hold:
  - Rust, egui 0.37, mise, prek and `cargo deny`;
  - macOS, Windows and Linux;
  - the window only sends `UiCommand`s and reads the frame;
  - library writes go through the writer;
  - plan 12a's compact look;
  - no network or real Trash in tests.

## Decisions this plan makes

- **The job model** (in `crates/ui/src/model.rs`):
  - `JobKind { Analysis, Covers, Scan, Import, Export, Stems }`.
  - `JobState { Running, Pausing, Paused }`.
  - `JobView` has these fields:
    - `kind: JobKind`;
    - `label: String`, e.g. "Analysing", "Covers", "Scanning Music…", "Reading VirtualDJ…", "Separating stems";
    - `done: Option<usize>` and `total: Option<usize>`, both `None` for an indeterminate job;
    - `eta: Option<Duration>`;
    - `state: JobState`;
    - `current: Option<String>`, the item it is on, shown on hover;
    - `note: Option<String>`, e.g. "Waiting for network";
    - `can_pause: bool` and `can_stop: bool`;
    - `locked: Option<&'static str>`, the tooltip shown when the buttons are disabled.
  - `ControlFrame.jobs: Vec<JobView>`, ordered by `JobKind`.
- **The command:** `UiCommand::Job { kind: JobKind, op: JobOp }`, with `JobOp { Pause, Resume, Stop }`.
- **The time left:** `app::session::jobs::Pace`.
  - It keeps `(Instant, done)` samples over the last 60 s.
  - It gives an `eta` only once at least 3 items are done and the job has run 5 s or more.
  - It measures the rate over its window, resets when `total` shrinks, and returns `None` while paused.
- **The time-left text:** `ui::footer::eta_text(Duration) -> String`:
  - under 90 s gives "~1 min";
  - under 60 min gives "~N min", with N rounded;
  - otherwise "~N h", rounded to whole hours, at least 1.
- **The list facts:** `BrowserView.list_seconds: Option<f64>`, the sum of the list's track durations. The library computes it in the same query as `list_count`. It is `None` for a folder list, which counts files.
- **Footer text:**
  - Left: "<list name> · N tracks · 2 h 31 min". The text is "N selected" when `all_selected` is set. A folder list says "N files".
  - The middle shows, in this order:
    1. `frame.error`, in the error colour;
    2. else the newest event, if under `EVENT_SHOWN` (8 s) old;
    3. else whatever else is left in the status text: the deck lines.
- **Truncation when narrow:** the time left goes first, then the list's total length, then the message, which is cut with "…". Pills never wrap; when they don't fit, the rightmost ones collapse to their label plus bar.

## Review Focus

1. A 1024 pt window with four decks and three jobs running: the footer stays one line, and the message is cut before any pill overflows. Owner: Task 1.
2. Pause analysis, then play a deck and stop it: analysis stays paused. Owner: Task 2.
3. New tracks queue while analysis runs, so `total` grows: done ≤ total, the ETA recomputes, and nothing goes negative. Owner: Task 2.
4. The cover lookup is offline: the pill says "Waiting for network", shows no ETA, and makes no request while paused. Owner: Task 3.
5. Stop an export halfway, then export again: the stick opens in each app's reader, and the second export completes it. Owner: Task 5.

  - `crates/app/src/library_mode/stem_jobs.rs`, which handles the stems queue: one pill, "Separating stems 2 / 5";
  - `crates/app/src/session/import.rs`, which handles the import pill and its stop;
  - `crates/app/src/session/jobs.rs`.
- Test: in those modules.

**Interfaces:**
- Produces:
  - `StemsControl::queue_progress(&self) -> Option<(usize, usize)>`, giving done and total for the current queue;
  - `StemsControl::pause(&mut self, bool)`;
  - `StemsControl::stop_all(&mut self)`.
  - The import stages map to the labels "Reading VirtualDJ…" and "Writing playlists…".
- **What can be paused or stopped:**
  - The scan is indeterminate ("Scanning <folder>…"). Its `can_pause` and `can_stop` are `false`, because a scan is short and its result is needed.
  - The import can be stopped only before its write starts. During the write, `can_stop` and `can_pause` are `false`, and `locked` is "The import is writing; it can't be stopped now."
  - A stopped one-shot job (the import, a stem queue) does not come back on its own.

  - `a_scan_shows_an_indeterminate_pill`.

  - `stopping_stems_cancels_the_queue_and_it_does_not_return`.
  - `the_import_can_be_stopped_before_it_writes_and_nothing_changes`. This test checks that no playlist or hotcue changed.

- [ ] **Step 2: Run them and see them fail. Step 3: Implement. Step 4: Run** `cargo test -p open-jockey`.

### Task 5: The USB export in the footer, stoppable between files

**Files:**
- Modify:
  - `crates/interop/src/export/run.rs`: `run` takes a `control: &dyn Fn(ExportProgress) -> ExportControl`, with `ExportControl { Go, Stop }`, in place of `progress`. Pause blocks inside the session's callback until resume or stop.
  - `crates/app/src/session/export.rs`.
  - `crates/app/src/session/jobs.rs`.
- Test: `crates/interop/tests/export.rs` and the session export tests.

**Interfaces:**
- Produces:
  - `ExportControl`;
  - `ExportReport.stopped: bool`.
- **On Stop:**
  - Stop is checked only between files.
  - A stopped run writes no Serato, Rekordbox or VirtualDJ library file, so the previous ones stay.
  - The files already copied stay.
  - The manifest records only what a finished run wrote, so the next export completes the stick.
  - The event reads "Export stopped: N of M files copied; the stick keeps its previous playlists".

- [ ] **Step 1: Write the failing tests.**
  - `a_stopped_export_leaves_the_previous_databases`. Export once, then export a bigger playlist and stop after 2 files. Check that every database file is byte-identical to the first export, and that each reader in the `interop` tests still parses the stick.

## Hands-on (the owner)

1. Open a playlist and a folder: the footer shows the name, the count and the length. Press Cmd+A, and it shows "N selected".
2. Delete something, or load a deck: the message shows in the footer, and the top bar no longer has it.
3. Add a folder of new tracks:
   - The analysis pill shows a count, a bar and the time left.
   - Pause it, play a deck, and check it stays paused. Resume, then Stop.
4. Covers: watch the pill, then pause it, resume it and stop it.
5. Export a playlist to a stick and stop it halfway. Check that VirtualDJ, Serato and Rekordbox still open the stick, then export again to finish it.
6. Quit while something is paused and relaunch: the jobs start again on their own.
7. The results go in `controllers/ddj-sb3/README.md`.
