# Plan 11c: Export to a USB Stick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner ticks playlists in the window (or names them on the CLI), picks a USB stick,
and one export writes everything Serato, Rekordbox (XML) and VirtualDJ need to open those
playlists in order, with their hotcues, saved loops and colours.

**Architecture:** A new `export` module in the `interop` crate does the work in three phases:
`gather` reads the library into an `ExportSet`; `plan_export` lays the set out on the stick
(names, copy or keep, free space, stale files) and writes nothing; `run` copies the music and
writes each format's files through one `StickFormat` trait (Serato, Rekordbox, VirtualDJ),
every file going to a temporary name and then renamed into place. The CLI
(`library export`) and a new "USB export" settings page drive the same three calls; the window
runs them on a thread, as the VirtualDJ import does.

**Tech Stack:** Rust; quick-xml 0.42 (already used), lofty 0.25.5 (ID3v2 `GEOB` frames in MP3
and WAV), base64 0.23, percent-encoding 2, serde + toml (the stick's manifest), fs4 (free
space), egui 0.37 / egui_kittest.

**Spec:** `docs/superpowers/specs/2026-11-09-interop-design.md` (goal 1, "What goes on an
exported stick", "Positions, grids and colours", "Stick details to verify against the apps",
"Verification", "Constraints"). Plan 11b (guest sticks) is postponed by the owner until they
have sticks made by the other apps; nothing here depends on it.

## Global Constraints

- Everything from the project still holds: mise, prek, Conventional Commits (commitizen),
  `cargo clippy --all-targets -- -D warnings`, `cargo fmt`, `cargo deny check`; builds and tests
  on macOS, Windows and Linux (CI runs all three).
- **Never modify the owner's own audio files.** Serato tags are written only into the
  **copies** on the stick, never the originals. Tests assert the original's bytes are
  unchanged.
- **Never write to a volume that holds a library folder** (the owner's music drive carries their
  VirtualDJ data) and never to a directory that is, contains or is inside a library folder.
- "A stick that looks exported but opens wrong (wrong order, cues shifted, tracks missing) is a
  failure even if the files are there. Unverified formats are not shipped as working." Docs say
  the formats are verified only after the owner's hands-on (end of this plan).
- "Interrupted exports (stick pulled, app closed) must leave the stick usable: each library file
  (crate, XML, database) is written to a temporary name and renamed into place; a half-copied
  track is removed or redone on the next export."
- "Before copying: check free space and show what will be written; a stick that is too small is
  refused before anything is written."
- "Exporting again skips tracks already there unchanged ... and copies only new or changed ones."
- Serato tags for **MP3 and WAV** only; other types are copied without Serato cues and the
  summary says how many.
- On the stick, Open Jockey only ever changes or deletes files it wrote itself (listed in its
  manifest) or, inside a shared library file (Serato's `database V2`, VirtualDJ's
  `database.xml`), only entries pointing into `Open Jockey/`. Everything else is kept byte for
  byte.
- Tests never touch the owner's real config, data, VirtualDJ folders, `/Volumes` or a real
  stick: temp dirs and generated audio only (no copyrighted music in the repo).
- Export is a prep task done with the mouse in the window; it must not block the control loop
  (work runs on its own thread) and it does not need the decks empty (it only reads the
  library).

## Review Focus

1. **The same track twice in a playlist, or in two exported playlists:** copied once, listed in
   every place it appears, in order, in all three formats (Task 7 test
   `shared_tracks_are_copied_once_and_listed_everywhere`).
2. **Names with FAT-illegal characters, non-ASCII and emoji, reserved names (`CON`), and two
   tracks with the same file name:** safe, unique, stable stick paths, and the same text survives
   into the XML (escaped) and the UTF-16 crates (Task 2 tests, Task 5 `escapes_and_encodes_names`).
3. **Re-export after editing only hotcues:** no track is copied again, only the changed copies
   are re-tagged, and every format shows the new cues (Task 7
   `reexport_after_hotcue_edit_retags_without_copying`).
4. **A failure in the middle (stick pulled, write refused):** an error, no panic, the stick still
   opens with the previous export's playlists, and the next export cleans up leftovers (Task 7
   `failed_write_leaves_previous_export_usable`).
5. **A stick already holding someone's Serato or VirtualDJ data:** their crates, database
   entries, songs and lists are kept untouched (Task 3 `merge_keeps_foreign_records`, Task 6
   `keeps_foreign_songs_byte_for_byte`, Task 7 `foreign_files_survive_export`).

## Decisions this plan makes (my calls, within the spec's "left to the builder")

- **Stick layout:**
  - `Open Jockey/Music/<Artist>/<file>`: the copies;
  - `Open Jockey/rekordbox.xml`;
  - `Open Jockey/README.txt`;
  - `Open Jockey/export.toml`: the manifest of what Open Jockey wrote;
  - `_Serato_/database V2` and `_Serato_/Subcrates/<playlist>.crate`;
  - `VirtualDJ/database.xml` and `VirtualDJ/MyLists/<playlist>.vdjfolder`.
- **The stick mirrors the ticked playlists.** Each export writes exactly the chosen playlists.
  Open Jockey playlists, crates, lists and copies from an earlier export that are no longer
  chosen are removed, but only those the manifest lists. The window ticks the playlists already
  on the chosen stick by default, so adding a set means ticking one more.
- **Skip rule:** a track is kept, not copied, when its stick path exists and
  `library::fingerprint::of_file(stick copy)` equals the track's library fingerprint. The
  fingerprint hashes decoded audio, so Serato tags on the copy do not change it. Copies are
  re-tagged only when their Serato frames differ from the new ones.
- **Main cue:** exported only to Rekordbox, as a memory cue. Serato's tags have no main cue, and
  VirtualDJ does not store one (seen in plan 11a).
- **VirtualDJ grid:** not written. VirtualDJ analyses the track itself; the spec records that the
  owner found the BPMs match. Saved-loop `Size` is in beats from Open Jockey's BPM. A loop on a
  track without a BPM is left out of VirtualDJ's data and counted in the summary.
- **Timing:** each app's position comes from one function, `export::timing::app_seconds`. Its
  starting values are a hypothesis that the hands-on calibrates (see Task 1). If the hands-on
  finds a shift, only the constants in `timing.rs` change.
- **Name clash with someone's crate or list of the same name:** ours becomes
  `<name> (Open Jockey)`.
- **Rekordbox `Location`:** the stick's path as mounted now (`file://localhost/Volumes/<stick>/…`
  on macOS). README.txt explains Rekordbox's "Relocate" for a computer that mounts the stick
  elsewhere (a Windows drive letter).
- A Serato `database V2` or VirtualDJ `database.xml` already on the stick that cannot be parsed:
  the export is **refused** at the planning step. Merging is not possible, and overwriting would
  lose someone's data.

### Task 2: Stick layout, manifest, safe files, and the export plan

**Files:**
- Create: `crates/interop/src/export/layout.rs`, `plan.rs`, `files.rs`
- Test: `crates/interop/tests/export_plan.rs`, unit tests in `layout.rs` and `files.rs`

**Interfaces:**
- Consumes: `ExportSet`, `ExportTrack`, `ExportError` (Task 1).
- Produces:
  - Constants: `OJ_DIR = "Open Jockey"`, `MUSIC_DIR = "Music"`, `MANIFEST = "export.toml"`,
    `PART_SUFFIX = ".ojpart"`, `SPACE_MARGIN: u64 = 32 * 1024 * 1024`.
  - `safe_component(text: &str, max_chars: usize) -> String`:
    - each of `< > : " / \ | ? *` and each control character becomes `_`;
    - trailing spaces and dots are trimmed;
    - empty text becomes `_`;
    - a Windows device name (`CON PRN AUX NUL COM1-9 LPT1-9`, any case, with or without an
      extension) gets `_` appended to its stem;
    - the result is cut to `max_chars` characters. For a name with an extension the cut keeps
      the extension.
  - `stick_paths(tracks: &[ExportTrack]) -> HashMap<i64, String>`:
    - each path is relative to the stick root, with `/` separators:
      `Open Jockey/Music/<safe artist, 60>/<safe file name, 120>`;
    - an empty or missing artist becomes `Unknown Artist`;
    - paths are assigned in ascending track id;
    - a clash is compared case-insensitively (full Unicode lowercase); it gets ` (2)`, ` (3)`, …
      before the extension.
  - `Manifest { version: u32, playlists: Vec<String>, crates: Vec<String>, vdj_lists:
    Vec<String>, tracks: Vec<String> }` (serde, `version = 1`):
    - `Manifest::read(stick: &Path) -> Result<Option<Manifest>, ExportError>`; a missing file is
      `None`; an unparsable one is `Refused("Open Jockey's manifest on the stick is damaged:
      …")`;
    - `Manifest::write(&self, stick: &Path) -> Result<(), ExportError>`, written atomically.
  - `files::write_atomic(path: &Path, bytes: &[u8]) -> Result<(), ExportError>`: writes
    `<path>.ojpart`, syncs it, renames it over `path`, and creates parent dirs.
  - `files::copy_atomic(from: &Path, to: &Path, then: impl FnOnce(&Path) -> Result<(),
    ExportError>) -> Result<(), ExportError>`: copies to `<to>.ojpart`, runs `then` on the temp
    file (Serato tagging), syncs, and renames.
  - `files::remove_leftovers(dir: &Path) -> Result<usize, ExportError>`: deletes every
    `*.ojpart` below `dir` without following symlinks.
  - `TrackAction { Copy, Keep }`
  - `PlannedTrack { pub track: ExportTrack, pub stick_path: String, pub action: TrackAction }`
  - `ExportPlan { pub stick: PathBuf, pub tracks: Vec<PlannedTrack>, pub playlists:
    Vec<ExportPlaylist>, pub skipped: Vec<Skipped>, pub copy_bytes: u64, pub free_bytes: u64,
    pub without_serato_cues: usize, pub stale_tracks: Vec<String>, pub previous:
    Option<Manifest> }`, with `fn too_small(&self) -> bool { self.copy_bytes + SPACE_MARGIN >
    self.free_bytes }`.
  - `plan_export(set: ExportSet, stick: &Path, library_folders: &[PathBuf]) -> Result<ExportPlan,
    ExportError>`: writes nothing.

### Task 3: Serato's bytes: crates, database V2, Markers2, BeatGrid, colours

**Files:**
- Create: `crates/interop/src/export/serato/{mod.rs, tlv.rs, markers.rs}` (`mod.rs` only declares
  the modules in this task)
- Test: unit tests in `tlv.rs` and `markers.rs`

**Interfaces:**
- Consumes: `ExportTrack`, `timing::app_seconds(App::Serato, …)` (Task 1).
- Produces:
  - `tlv::Record { tag: [u8; 4], body: Body }`, with `Body::Records(Vec<Record>)` for tags
    starting `o`, and `Body::Bytes(Vec<u8>)` for everything else.
    - `tlv::text(tag, &str) -> Record`: UTF-16BE, no terminator.
    - `tlv::u32_rec(tag, u32) -> Record`: big-endian.
    - `tlv::encode(&[Record]) -> Vec<u8>`: 4-byte ASCII tag, `u32` big-endian length, body.
    - `tlv::decode(&[u8]) -> Result<Vec<Record>, String>`: parses records recursively for `o`
      tags; a record that runs past the end is an error.
  - `tlv::crate_file(stick_paths: &[&str]) -> Vec<u8>`:
    - `vrsn` = `"1.0/Serato ScratchLive Crate"`;
    - four `ovct` columns, each `{tvcn <name>, tvcw "0"}`, for `song`, `artist`, `bpm`, `key`;
    - one `otrk { ptrk <path> }` per entry, in order.
    - Paths are relative to the stick root, with no leading `/`.
  - `tlv::database_record(t: &ExportTrack, stick_path: &str, added: u32) -> Record`: `otrk` with
    `ttyp` (lowercase extension), `pfil` (path), `tsng` title, `tart` artist, `talb` album,
    `tgen` genre, `tbpm` (`format!("{:.2}")`), `tkey`, and `uadd` (u32, Unix seconds). A field
    whose value is `None` is left out.
  - `tlv::merge_database(existing: Option<&[u8]>, ours: Vec<Record>) -> Result<Vec<u8>, String>`:
    - the result starts with `vrsn` = `"2.0/Serato Scratch LIVE Database"`;
    - it keeps every existing record, in order, except `otrk` records whose `pfil` starts with
      `Open Jockey/`;
    - our records go at the end.
  - `markers::SERATO_CUE_COLORS: [u32; 18]` = `[0xCC0000, 0xCC4400, 0xCC8800, 0xCCCC00, 0x88CC00,
    0x44CC00, 0x00CC00, 0x00CC44, 0x00CC88, 0x00CCCC, 0x0088CC, 0x0044CC, 0x0000CC, 0x4400CC,
    0x8800CC, 0xCC00CC, 0xCC0088, 0xCC0044]`.
  - `markers::SLOT_DEFAULT_COLORS: [u32; 8]` = `[0xCC0000, 0xCC8800, 0x0000CC, 0xCCCC00, 0x00CC00,
    0xCC00CC, 0x00CCCC, 0x8800CC]`.
  - `markers::LOOP_COLOR: [u8; 4] = [0x00, 0x27, 0xAA, 0xE1]`.
  - `markers::serato_color(color: Option<u32>, slot: u8) -> u32`: the nearest entry of
    `SERATO_CUE_COLORS` by hue. Grey or black (saturation < 0.15) gives the slot default, as
    does `None`.
  - `markers::markers2_payload(t: &ExportTrack) -> Vec<u8>`: the decoded content.
  - `markers::markers2_geob(t: &ExportTrack) -> Vec<u8>`: the GEOB frame's data.
  - `markers::beatgrid_geob(t: &ExportTrack) -> Option<Vec<u8>>`: `None` without a BPM or first
    beat.

**The bytes** (from the community documentation of Serato's tags; the hands-on is the proof):
- **Markers2 decoded content:**
  - it opens with `01 01`;
  - then the entries, in this order: `COLOR`, each `CUE` by slot, each `LOOP` by slot, then
    `BPMLOCK`;
  - it ends with one `00` byte;
  - each entry is `<ASCII name> 00`, then a `u32` big-endian length, then the data.
- **Entry data:**
  - `COLOR`: `00 FF FF FF`.
  - `CUE`: `00`, index (slot − 1), position in ms (`u32` BE, rounded), `00`, RGB (3 bytes from
    `serato_color`), `00 00`, then the name as UTF-8 with a `00` terminator (an empty name is
    just `00`).
  - `LOOP`: `00`, index, start ms, end ms (`u32` BE each), `FF FF FF FF`, `LOOP_COLOR`, `00`,
    locked `00`, then the name as UTF-8 with a `00` terminator.
  - `BPMLOCK`: `00`.
- **The GEOB data:**
  - `01 01`, then `base64(decoded content)`: standard alphabet, `=` padding removed, a `\n`
    after every 72 base64 characters;
  - then `00` bytes padding the whole to at least 470 bytes.
- **BeatGrid GEOB data:** `01 00`, `00 00 00 01` (one marker), position (`f32` BE, Serato
  seconds of the first beat), BPM (`f32` BE), footer `00`.
- Slot index and positions use `app_seconds(App::Serato, …)` × 1000, rounded.

- Produces (ui):

  - `ExportStep { Open, Check { stick: usize, playlists: Vec<i64> }, Write, Back, Close }`.
    `Open` (re)lists the sticks and playlists. `Back` returns from the summary to the choice.
    `Close` puts a result away.
  - `ExportView { #[default] Idle, Listing, Choose(ExportChoice), Checking, Summary(ExportSummary),
    Writing { done: usize, total: usize }, Done(String), Failed(String) }`
  - `ExportChoice { pub sticks: Vec<StickLabel>, pub playlists: Vec<PlaylistLabel> }`
  - `StickLabel { pub name: String, pub free: String, pub exported: Vec<i64> }`: `exported` holds
    the ids of library playlists whose names are in that stick's manifest.
  - `PlaylistLabel { pub id: i64, pub name: String, pub tracks: u32 }`
  - `ExportSummary { pub stick: String, pub playlists: usize, pub tracks: usize, pub to_copy:
    usize, pub copy_size: String, pub kept: usize, pub free: String, pub without_serato_cues:
    usize, pub skipped: usize, pub to_remove: usize, pub too_small: bool }`

## Hands-on (the owner, after the final review)

Needs one empty USB stick, the free **Serato DJ Lite** and **Rekordbox** installed on the Mac,
and VirtualDJ.

1. **Timing calibration track** (not committed), made with:

   ```
   ffmpeg -f lavfi -i "aevalsrc='if(lt(mod(t,0.5),0.004),0.9*sin(2*PI*2000*t),0)':s=44100:d=60" -c:a libmp3lame -b:a 320k ~/Music/oj-click.mp3
   ```

   Make a WAV copy too (`-c:a pcm_s16le oj-click.wav`). Add both to the library and analyse them
   (120 BPM). Put hotcue 1 on the click at 8.0 s and a 4-beat saved loop at 16.0 s, with the
   waveform zoomed in, in a playlist `OJ click`.
2. Export `OJ click` and one real prep playlist to the stick from **Settings → USB export**.
3. In each of Serato DJ Lite, Rekordbox (after the XML import) and VirtualDJ, check:
   - the playlist order;
   - the hotcue and loop positions: at full zoom, hotcue 1 sits on the click's start;
   - loop lengths, colours and names.

   For the click MP3, write down any shift per app. A shift means changing the constants in
   `export/timing.rs`, then re-checking.
4. Re-export after moving one hotcue: Open Jockey copies nothing and the app shows the new
   position. Untick a playlist and export: it is gone from all three apps.
5. Put one track twice in a playlist and export it: Serato's crate keeps both entries, in
   order (check Rekordbox and VirtualDJ too).
6. VirtualDJ lists name each track by its absolute path: plug the stick into another computer
   (or rename the stick so it mounts under another name) and check that VirtualDJ still finds
   the tracks of each list under the stick's Lists folder.
7. Record the results in `controllers/ddj-sb3/README.md`, then mark the formats verified in
   `docs/interop.md`.
