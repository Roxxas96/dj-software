# UI: the Screen You Play On (Plan 9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `open-jockey` with no arguments opens a VirtualDJ-Pro-style window (scrolling frequency-coloured waveforms, two deck panels, the mixer, a folder-based browser) that mirrors the DDJ-SB3 live, so the owner plays a whole set without the terminal.

**Architecture:**
- **New `ui` crate (egui via `eframe`).** It knows nothing about MIDI, the database or audio devices. It draws from two sources:
  - an `EngineMonitor`, the engine's lock-free snapshots, read every frame for the waveforms and transport;
  - a `ControlFrame` the control thread publishes after every change: the controller state, the browser, deck track info and status.
- **The `app` crate runs a "session".**
  - The existing control loop runs on its own thread with the library (as `play --library` does), its terminal printer redirected to the window.
  - The main thread runs the window.
  - Closing the window stops the session, which saves cues as `play` does at Ctrl-C.

**Tech Stack:**
- Rust 2024 and `eframe`/`egui` (current release), with `egui_kittest` for headless widget tests;
- the existing `engine`, `actions`, `controller`, `library`, `analysis` and `audio-io` crates;
- `lofty` (already a dependency) for cover art.

**Spec:** `docs/superpowers/specs/2026-11-08-ui-design.md` ("Goals: plan 9" and everything not marked plan 10). Background: `docs/superpowers/specs/2026-10-30-dj-software-design.md#interface`.

## Global Constraints

- License Apache-2.0, no GPL; `cargo deny` must pass. egui's bundled fonts are OFL-1.1 / Ubicloud licensed: add exactly the licenses the new crates need to `deny.toml`, each with a comment.
- macOS, Windows and Linux build and pass CI. Built for a MacBook screen (Retina, 14 to 16 inch), scaling to larger ones.
- **Drawing never slows down or interrupts playback.**
  - The UI only reads the engine's seqlock snapshots and the published `ControlFrame`.
  - It never sends engine commands in plan 9.
  - The control thread never waits on the UI: publishing is one pointer swap.
- **Waveforms scroll at the display's refresh rate.** The playhead shows what is heard: the snapshot position extrapolated to now, minus the output latency.
- **The screen never shows a state the SB3 or the app doesn't have.** No MASTER/SYNC badge. The pad mode name is the last mode button pressed, "pads" until then.
- **One audio device,** as `play` does today (master and headphone channel pairs on it).
- **Open Jockey's own look.** VirtualDJ's layout, terminology and dark style, but no VirtualDJ logo, icons, images or fonts.
- **Config errors** read `<file>: <key>: <problem>`; every new key is documented in `docs/config.md`.
- **The terminal stays as it is:** `play` (with and without `--library`), `library`, `stems` and `midi`.
- **Conventional Commits.** Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `controllers/ddj-sb3/capture.toml`. Never send personal data to any service.

## Review Focus

1. **A deck with a track but no beatgrid yet** (analysis pending): its lane scrolls with no ticks and no panic. Ticks, with red bar ticks, appear as soon as the grid arrives. Tested in Task 7.
2. **DECK pressed mid-transition while both decks play:** the switched-away deck keeps its lane until it stops. Tested in Task 8 (`lanes_keep_playing_decks`).
3. **A folder that can't be read, or a drive unplugged while open:**
   - the browser shows the folder empty with a "cannot read" note, and BROWSE keeps working;
   - a 5,000-file folder lists without blocking the knob.
   Tested in Task 3.
4. **Closing the window while a deck plays with an unsaved hotcue:** the hotcue is saved before the process exits. Tested in Task 6.
5. **The same track reloaded, or a new track loaded before the detail waveform is ready:** a stale waveform never draws on the new track. Tested in Task 7 (keyed by `load_seq`).

### Task 3: Folder-tree browser

**Files:**
- Modify: `crates/library/src/browser.rs` (becomes `browser/mod.rs`), `crates/library/src/playlists.rs` (`TrackFilter.folder_only`), `crates/library/src/lib.rs`

**Interfaces:**
- Consumes: `BrowserRequest::{Scroll(i32), ToggleFocus, ToggleFolder}` (Task 2).
- Produces:
  - **`library::drives() -> Vec<Drive>`**, with `Drive { name: String, path: PathBuf }`:
    - **macOS:** `/` named by the volume's name (fallback "Macintosh HD"), then each entry of `/Volumes` that isn't a link to `/`;
    - **Windows:** each existing drive letter;
    - **Linux:** `/` ("Computer"), then the entries of `/media/$USER` and `/mnt`.
  - **`Browser::with_roots(reader: Reader, roots: Vec<Drive>) -> Result<Browser, LibraryError>`.** `Browser::new(reader)` calls it with `drives()`. Tests pass temp folders as roots.
  - **Tree:** the roots (collapsed), then a "Playlists" node, expanded, with one child per playlist.

    - Scroll moves over visible rows only.
  - **The list** for a highlighted folder is its own audio files, not recursive, sorted by file name.
    - A library track's row is used when the file is in the library (`TrackFilter { folder: Some(dir), folder_only: true, .. }`).
    - Other files get a row from the file name alone.
    - For a playlist, the list is its tracks, as today.
  - **`BrowserView` gains:**
    - `tree: Vec<TreeRow>`, every visible tree row: `TreeRow { label: String, depth: u8, kind: TreeKind { Drive, Folder, Playlists, Playlist }, expanded: bool, note: Option<&'static str> }`;
    - `tree_cursor: usize`;
    - `list: Vec<ListRow>`, the rows of the loaded page, with `list_offset: usize`, `list_count: usize` and `list_cursor: usize`;
    - `ListRow { path: PathBuf, track: Option<TrackRow>, file_name: String }`.
    The existing `path`, `index`, `count`, `track` and `focus` fields stay, so the terminal browser line is unchanged.
  - **`library::remix_of(title: &str) -> Option<&str>`:** the text in the last `(...)` or `[...]` of a title, trimmed. It is the Remix column (VirtualDJ shows the mix name there).
  - **`Reader::waveform(&self, track_id: i64) -> Result<Option<Waveform>, LibraryError>`.**
- **Reads stay off the control loop.** Folder reads run on the library worker thread that already runs browser requests. A `read_dir` of the highlighted folder happens once per highlight move. A folder with more than 200 files reads one page around the cursor (`BROWSER_PAGE_ROWS`).

### Task 7: Waveform data: colour, ticks, playhead, detail

**Files:**
- Create: `crates/ui/src/waveform/{mod.rs,colour.rs,ticks.rs,playhead.rs}`, `crates/app/src/session/detail.rs`
- Test: unit tests in each file

**Interfaces:**
- Produces:
  - **`ui::waveform::colour(bucket: [u8; 4]) -> egui::Color32`:** `bucket` is `[peak, low, mid, high]`.
    - Normalise `low`, `mid` and `high` by their sum. A sum of 0 gives the dim text colour.
    - Blend three anchors: low `#ff3a1f` (red-orange), mid `#ff9ad5` (pink), high `#ffffff` (white).
    - Brightness scales with `peak`, never below 35 %.
    - These anchors are the starting point the owner tunes by eye at the hands-on. Keep them as named constants.
  - **`ui::waveform::ticks(grid: Option<engine::Grid>, from_frame: f64, to_frame: f64) -> Vec<Tick>`**, with `Tick { frame: f64, bar: bool }`:
    - every beat `first_beat_frames + k * beat_period_frames` in range;
    - `bar` when `k.rem_euclid(4) == 0`;
    - empty for `None`.
  - **`ui::waveform::Playhead`:**
    - `observe(&mut self, snapshot: &DeckSnapshot, now: Instant)`;
    - `position(&self, now: Instant, latency: Duration) -> f64` in track frames.
    Between snapshot changes, while `playing` and not `jog_touched` and not `backspinning`, it extrapolates by `tempo_ratio × track_sample_rate × elapsed`, capped at 100 ms past the last observed change. Otherwise it returns the snapshot position. It then subtracts `latency × tempo_ratio × rate` when playing.
  - **Latency:** `ControlFrame.output_latency` (Task 6).
  - **`app::session::detail::DetailJobs`:**
    - On each deck load observed in a snapshot (new `load_seq` with `loaded`), a background thread computes `analysis::waveform(&track, 128)` from the deck's `TrackBuffer` (the library mode holds the loaded `Arc<TrackBuffer>`; pass it in).
