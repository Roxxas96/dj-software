# Plan 8: Stems

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** VirtualDJ-style stems on the owner's DDJ-SB3:
- **Separation:** four stems per track (vocals, instruments, bass, rhythm), separated locally by an open-source model.
- **Stems mode:** in `config.toml`, the EQ knobs become stem knobs (HI = vocals, MID = instruments, LOW = bass, with right-of-center isolating).
- **Stem pads:** four on/off actions the user binds where they like.
- **Cache:** separated stems are kept within a size budget, so reloading is instant.
- **Mapping `extends`:** a user mapping can build on the built-in one.

**Architecture:**
- **A new `stems` crate** owns the `Separator` trait, a synthetic separator for tests, the real model backend chosen by Task 1's trial, and `stems setup` (the one-time model download with a checksum).
- **The library** owns the stem cache (files plus a table, eviction) and records when tracks are loaded.
- **The engine:**
  - A deck can hold a `StemSet` beside its track, mixing three stored stems and the derived fourth with per-stem gains.
  - The renderer computes those gains from the channel's EQ knob positions (the knob law) when stems mode is on and the deck's stems are ready, and the mixer then bypasses that channel's EQ.
- **The app** finds or schedules separation on load, sends stems to the deck when ready, and shows progress on the status line.

**Spec:** `docs/superpowers/specs/2026-11-08-stems-design.md`. It is approved and binding; read its "Settled after the builder check" section. It extends `docs/superpowers/specs/2026-10-30-dj-software-design.md`.

**Tech Stack:** Rust 1.99.1. New dependencies are decided by Task 1 within the license rules below.

## Global Constraints

- **License: Apache-2.0; no GPL.** The model (code and weights) and every new dependency must be permissive (MIT/Apache/BSD/ISC/Zlib), and `cargo deny` passes.
- **No network at run time.** Only `open-jockey stems setup` downloads anything: the model, from a fixed URL, verified by a pinned SHA-256. No audio ever leaves the computer.
- **Builds and tests on macOS, Windows and Linux.** CI has no audio, MIDI or GPU devices, and no model file: tests use the synthetic separator.
- **The audio thread never allocates, frees, locks or blocks.** Stem sets arrive through the command queue and leave through the garbage queue. `no_alloc.rs` covers every new path.
- **Anti-goals:**
  - no freeze, crash or dropout;
  - a control does only what its mapping says;
  - cues never disappear;
  - switching a deck from EQ to stems never changes what is heard: with knobs centered, the stems sum exactly to the track, and the changeover is crossfaded;
  - a cache problem never blocks playing a track;
  - no audio leaves the computer.
- **Knob law** (verbatim from the spec):
  - `own = min(1, 2p)` and `iso = max(0, 2p − 1)` for each of HI (vocals), MID (instruments) and LOW (bass);
  - `I = max_k iso_k`;
  - a knob stem with `iso > 0` gets `own` (= 1), one with `iso = 0` gets `own × (1 − I)`, and rhythm gets `1 − I`;
  - each is times the stem's pad flag, ramped over one block.
- **Config:** `[stems] enabled = false`, `eq_mode = "eq" | "stems"` (default `"eq"`) and `cache_gb = 5`. Errors are reported as `<file>: <key>: <problem>`.
- **Stems are refused for tracks longer than 20 minutes.**
- Conventional Commits, prek on every commit, branch `feat/plan-8-stems`, landing via PR.

## Review Focus

1. **Stems arriving while the knobs are off-center.** The changeover crossfades from the EQ path to the stem path over one block. The level may change (the knobs now mean stems), but there is no click, and with centered knobs there is no change at all. Test: Task 2, `centered_knobs_changeover_is_inaudible` and `changeover_has_no_click`.
2. **Loading another track while the previous one is still separating.** The old job is cancelled or its result discarded, and its stems never reach the new track. Test: Task 6, `stale_separation_never_reaches_a_new_track`.
3. **A corrupt, truncated or deleted cache file.** It is treated as missing: the knobs stay EQ, separation reruns and the entry is replaced. Test: Task 5, `corrupt_cache_entry_is_redone`.
4. **The cache over budget while every cached track is loaded in a deck.** Nothing loaded is evicted. The cache may stay over budget until a deck unloads, and that is logged. Test: Task 5, `loaded_stems_are_never_evicted`.
5. **No model installed, with stems enabled.** Tracks play with the EQ, and one startup message says how to run `stems setup`. Test: Task 6, `missing_model_is_reported_once`.

### Task 1: Trial: model, runtime and acceleration (decision record)

**Files:** Create `docs/stems-backend.md` (the decision record), and a throwaway trial outside the workspace members (`spikes/stems/` or the scratchpad) that is **not** committed.

**What to decide and measure**, on this Mac (the owner's MacBook):
- **Candidates:**
  - **Demucs v4** (`htdemucs`, MIT) run through **ONNX Runtime** with the CoreML execution provider, via a permissive Rust binding such as `ort`, keeping the STFT/iSTFT outside the graph if export needs it;
  - **demucs.cpp** (MIT, C++/Eigen, CPU), built with `cc`;
  - **candle** (MIT/Apache, pure Rust, Metal), if a Demucs port is practical.
- **Record for each:**
  - license (code and weights);
  - whether it builds on all three OSes;
  - separation time for a 5-minute 44.1 kHz stereo track on this Mac (accelerated and CPU);
  - peak memory;
  - model file size, download URL and SHA-256;
  - output order (which output is drums, bass, other or vocals).
- **Choose one.** The goal is 10-30 s per 5-minute track on this Mac, but it is not a gate (the spec allows slower).
- **Also choose the cache format.** The cache stores three stems (vocals, bass, rhythm); instruments is derived as `mix − (vocals + bass + rhythm)` at load, so the sum stays exact even with lossy compression. Pick a permissive encoder and decoder whose size is at most ~30 MB per 5-minute track (for example Opus or Vorbis at ~192 kbps via a permissive binding, or FLAC via `flacenc`). Record the measured size and encode/decode time.

### Task 2: Engine: stem sets, the knob law and the changeover

**Files:** Create `crates/engine/src/stems.rs` and `crates/engine/tests/stems.rs`. Modify `command.rs`, `deck/mod.rs` (the source reader), `mixer.rs`, `renderer.rs`, `shared.rs`, `lib.rs` and `tests/no_alloc.rs`.

**Interfaces:**
- **`pub struct StemSet`:**
  - It holds three stems, each `Box<[i16]>` interleaved stereo at the track's rate, in the order vocals, bass, rhythm, plus `frames`.
  - `StemSet::new(vocals, bass, rhythm, frames) -> Result<StemSet, StemError>` checks the lengths.
  - The fourth stem, instruments, is computed per frame as `mix − (vocals + bass + rhythm)` from the deck's track buffer.
- **Commands:**
  - `DeckCommand::SetStems(Option<Arc<StemSet>>)`. A replaced set goes to the garbage queue: generalize it to an enum, `Garbage { Track(Arc<TrackBuffer>), Stems(Arc<StemSet>) }`.
  - A set whose `frames` differ from the loaded track's is ignored and discarded.
  - `Load` clears stems.
  - `DeckCommand::StemOn(Stem, bool)` with `pub enum Stem { Vocals, Instruments, Bass, Rhythm }`. All are on after `Load`.
  - `MasterCommand::EqMode(EqMode)` with `pub enum EqMode { Eq, Stems }`, default `Eq`.
- **The source reader** (the single place the deck reads its track frame) returns, when the deck has stems and the channel is in stems mode, `Σ gain_s × stem_s` instead of the mix frame. Keylock, scratch, backspin, slip, loops, rolls and beat jump are unchanged downstream.
- **Gains:** the renderer computes the four gains per block from the channel's EQ knob positions with the knob law (Global Constraints) times the `StemOn` flags, and ramps them over the block. The mixer bypasses the EQ stage for a channel while its deck is in stem mode.
- **Changeover** (stems arriving, `EqMode` changing, or `SetStems(None)`): one block where the channel output crossfades from the EQ path to the stem path (or back).
- `DeckSnapshot.stems: bool` (stems present) and `stems_active: bool` (in use).

- [ ] **Step 1: Write the failing tests** in `crates/engine/tests/stems.rs`:
  - `knob_law_matches_the_spec`: a table of knob positions → gains, including HI and LOW fully right → vocals and bass 1, instruments and rhythm 0.
  - `centered_knobs_changeover_is_inaudible`: output identical, ±1e-4, before and after stems arrive with knobs centered and EQ at unity.
  - `changeover_has_no_click`: no sample step above 0.05 at the changeover with off-center knobs.
  - `stem_pads_mute_their_stem`.
  - `instruments_is_the_residual`.
  - `mismatched_stems_are_ignored`.
  - `load_clears_stems_and_resets_pads`.
  - `keylock_and_scratch_play_the_stem_mix` (stems on with one stem muted: the muted stem is absent from the stretched and the scratched output).
  - no_alloc: `SetStems`, replacing stems (garbage), `StemOn`, `EqMode`, and rendering with stems active on 4 decks.

### Task 4: The `stems` crate: separator, model setup

**Files:** Create `crates/stems/{Cargo.toml,src/lib.rs,src/synthetic.rs,src/model.rs,src/setup.rs}` and `crates/stems/tests/`. Modify the workspace `Cargo.toml`, `deny.toml` if needed, and `crates/app/src/main.rs` (`stems setup` subcommand).

**Interfaces:**
- `pub trait Separator: Send { fn separate(&mut self, track: &TrackBuffer, progress: &dyn Fn(f32), cancel: &AtomicBool) -> Result<StemSet, SeparateError>; }`
  - It returns `Cancelled` when the cancel flag is set, checked at least once per chunk.
- **`SyntheticSeparator`** (always built): a fixed linear split into vocals, bass and rhythm using simple bands, for tests.
- **`ModelSeparator`** (behind cargo feature `model`, on by default for release builds, off in CI if the backend cannot build there):
  - It wraps Task 1's chosen backend, with chunking and overlap per `docs/stems-backend.md`.
  - It maps the model's outputs to vocals, bass and rhythm (Demucs drums → rhythm, other → dropped, since instruments is the residual).
  - It uses acceleration on Apple silicon.
- **`stems::model_path() -> PathBuf`:** the per-user data folder `models/<name>`.
- **`stems::setup(progress) -> Result<(), SetupError>`:**
  - downloads from the URL recorded in Task 1;
  - verifies the SHA-256 and writes atomically (temp file, then rename);
  - is idempotent;
  - uses a permissive HTTP client (blocking `ureq` or similar).
- **`open-jockey stems setup`** prints progress and where the model went.

### Task 5: Library: the stem cache and load history

**Files:** Create `crates/library/src/stems_cache.rs` and `crates/library/tests/stems_cache.rs`. Modify `schema.rs` (a migration: `tracks.last_loaded_at INTEGER`, and a `stems` table with `track_id`, `fingerprint`, `path`, `bytes`, `prepared`, `created_at`), `writer.rs`, `lib.rs` and `crates/app/src/library_cmd.rs` (`library stems --playlist <name> | --track ID...`).

**Interfaces:**
- **`StemCache::new(dir, budget_bytes)`:**
  - `get(track, fingerprint) -> Option<StemSet>`: decodes the Task 1 format. Any error means `None`, and the entry is removed.
  - `put(track, fingerprint, &StemSet, prepared)`: encodes atomically (temp file, then rename), records the row, then evicts.
  - `evict(loaded: &[i64])`.
- **Eviction order:**
  1. tracks in no playlist, not prepared (no cue above 0 and no hotcue, and not `prepared`) and not loaded in the last 30 days;
  2. then the rest by oldest `last_loaded_at`.

  Never a track in `loaded`. It stops once under budget.
- **`WriteOp::TrackLoaded(track)`** sets `last_loaded_at = now`.
- **`library stems`** separates (with the `model` feature) and stores with `prepared = true`, printing progress per track. Without a model it explains `stems setup`.

### Task 6: App: separation on load and the status line

**Files:** Modify `crates/app/src/library_mode/{mod.rs,worker.rs}`, `crates/app/src/play.rs` and the tests in `library_mode`.

**Interfaces:**
- **On loading a library track with stems enabled**, after the load applies (`load_seq`):
  - Send `WriteOp::TrackLoaded`.
  - Look the track up in the cache, which is read on the worker: if found, send `SetStems`.
  - Otherwise queue a separation job on one background thread at low priority. Use the `SyntheticSeparator` in tests and the `ModelSeparator` with the feature and a present model. The job yields while any deck plays, as the analyzer does, and is cancelled when that deck loads another track.
  - On completion, if the deck still holds the same track (track id and `load_seq`), send `SetStems` and `put` it in the cache. Otherwise discard the result.
  - Tracks over 20 minutes are refused.
- **A missing model, with stems enabled,** gives one startup message ("stems: no model, run `open-jockey stems setup`") and nothing more.
- **Status line:**
  - `stems 40%` while separating;
  - `stems` when active;
  - `no stems (too long)` for refused tracks.

**Interfaces:**
- **A top-level `extends = "<built-in name or path>"`:**
  - The parent's `[controller]`, `[[init]]`, `[[input]]` and `[[output]]` are inherited.
  - The child's `[controller]` keys override the parent's, key by key.
  - A child `[[input]]` with the same MIDI message, `pad_mode` and `shift` as inherited bindings replaces them.
  - `[[remove]] midi = {…}`, with optional `pad_mode` and `shift`, deletes the matching inherited bindings.
- **Errors:** an unknown parent, a cycle, or a `[[remove]]` that matches nothing is a load error naming the file and the entry.
