# Plan 8: Stems

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** VirtualDJ-style stems on the owner's DDJ-SB3:
- **Separation:** four stems per track (vocals, instruments, bass, rhythm), separated locally by an open-source model.
- **Stems mode:** in `config.toml`, the EQ knobs become stem knobs (HI = vocals, MID = instruments, LOW = bass, with right-of-center isolating).
- **Stem pads:** four on/off actions the user binds where they like.
- **Cache:** separated stems are kept within a size budget, so reloading is instant.
- **Mapping `extends`:** a user mapping can build on the built-in one.

**Architecture:**
- **A new `stems` crate** owns the `Separator` trait, a synthetic separator for tests, the real model backend chosen by Task 1's trial, and `stems setup` (the one-time model download with a checksum).
- **The library** owns the stem cache (files plus a table, eviction) and records when tracks are loaded.
- **The engine:**
  - A deck can hold a `StemSet` beside its track, mixing three stored stems and the derived fourth with per-stem gains.
  - The renderer computes those gains from the channel's EQ knob positions (the knob law) when stems mode is on and the deck's stems are ready, and the mixer then bypasses that channel's EQ.
- **The app** finds or schedules separation on load, sends stems to the deck when ready, and shows progress on the status line.

**Spec:** `docs/superpowers/specs/2026-11-08-stems-design.md`. It is approved and binding; read its "Settled after the builder check" section. It extends `docs/superpowers/specs/2026-10-30-dj-software-design.md`.

**Tech Stack:** Rust 1.99.1. New dependencies are decided by Task 1 within the license rules below.

## Global Constraints

- **License: Apache-2.0; no GPL.** The model (code and weights) and every new dependency must be permissive (MIT/Apache/BSD/ISC/Zlib), and `cargo deny` passes.
- **No network at run time.** Only `open-jockey stems setup` downloads anything: the model, from a fixed URL, verified by a pinned SHA-256. No audio ever leaves the computer.
- **Builds and tests on macOS, Windows and Linux.** CI has no audio, MIDI or GPU devices, and no model file: tests use the synthetic separator.
- **The audio thread never allocates, frees, locks or blocks.** Stem sets arrive through the command queue and leave through the garbage queue. `no_alloc.rs` covers every new path.
- **Anti-goals:**
  - no freeze, crash or dropout;
  - a control does only what its mapping says;
  - cues never disappear;
  - switching a deck from EQ to stems never changes what is heard: with knobs centered, the stems sum exactly to the track, and the changeover is crossfaded;
  - a cache problem never blocks playing a track;
  - no audio leaves the computer.
- **Knob law** (verbatim from the spec):
  - `own = min(1, 2p)` and `iso = max(0, 2p − 1)` for each of HI (vocals), MID (instruments) and LOW (bass);
  - `I = max_k iso_k`;
  - a knob stem with `iso > 0` gets `own` (= 1), one with `iso = 0` gets `own × (1 − I)`, and rhythm gets `1 − I`;
  - each is times the stem's pad flag, ramped over one block.
- **Config:** `[stems] enabled = false`, `eq_mode = "eq" | "stems"` (default `"eq"`) and `cache_gb = 5`. Errors are reported as `<file>: <key>: <problem>`.
- **Stems are refused for tracks longer than 20 minutes.**
- Conventional Commits, prek on every commit, branch `feat/plan-8-stems`, landing via PR.

## Review Focus

1. **Stems arriving while the knobs are off-center.** The changeover crossfades from the EQ path to the stem path over one block. The level may change (the knobs now mean stems), but there is no click, and with centered knobs there is no change at all. Test: Task 2, `centered_knobs_changeover_is_inaudible` and `changeover_has_no_click`.
2. **Loading another track while the previous one is still separating.** The old job is cancelled or its result discarded, and its stems never reach the new track. Test: Task 6, `stale_separation_never_reaches_a_new_track`.
3. **A corrupt, truncated or deleted cache file.** It is treated as missing: the knobs stay EQ, separation reruns and the entry is replaced. Test: Task 5, `corrupt_cache_entry_is_redone`.
4. **The cache over budget while every cached track is loaded in a deck.** Nothing loaded is evicted. The cache may stay over budget until a deck unloads, and that is logged. Test: Task 5, `loaded_stems_are_never_evicted`.
5. **No model installed, with stems enabled.** Tracks play with the EQ, and one startup message says how to run `stems setup`. Test: Task 6, `missing_model_is_reported_once`.

### Task 2: Engine: stem sets, the knob law and the changeover

**Files:** Create `crates/engine/src/stems.rs` and `crates/engine/tests/stems.rs`. Modify `command.rs`, `deck/mod.rs` (the source reader), `mixer.rs`, `renderer.rs`, `shared.rs`, `lib.rs` and `tests/no_alloc.rs`.

**Interfaces:**
- **`pub struct StemSet`:**
  - It holds three stems, each `Box<[i16]>` interleaved stereo at the track's rate, in the order vocals, bass, rhythm, plus `frames`.
  - `StemSet::new(vocals, bass, rhythm, frames) -> Result<StemSet, StemError>` checks the lengths.
  - The fourth stem, instruments, is computed per frame as `mix − (vocals + bass + rhythm)` from the deck's track buffer.
- **Commands:**
  - `DeckCommand::SetStems(Option<Arc<StemSet>>)`. A replaced set goes to the garbage queue: generalize it to an enum, `Garbage { Track(Arc<TrackBuffer>), Stems(Arc<StemSet>) }`.
  - A set whose `frames` differ from the loaded track's is ignored and discarded.
  - `Load` clears stems.
  - `DeckCommand::StemOn(Stem, bool)` with `pub enum Stem { Vocals, Instruments, Bass, Rhythm }`. All are on after `Load`.
  - `MasterCommand::EqMode(EqMode)` with `pub enum EqMode { Eq, Stems }`, default `Eq`.
- **The source reader** (the single place the deck reads its track frame) returns, when the deck has stems and the channel is in stems mode, `Σ gain_s × stem_s` instead of the mix frame. Keylock, scratch, backspin, slip, loops, rolls and beat jump are unchanged downstream.
- **Gains:** the renderer computes the four gains per block from the channel's EQ knob positions with the knob law (Global Constraints) times the `StemOn` flags, and ramps them over the block. The mixer bypasses the EQ stage for a channel while its deck is in stem mode.
- **Changeover** (stems arriving, `EqMode` changing, or `SetStems(None)`): one block where the channel output crossfades from the EQ path to the stem path (or back).
- `DeckSnapshot.stems: bool` (stems present) and `stems_active: bool` (in use).

## Addendum: knob layouts and extra pads (tasks 9–12)

**Goal:** after the owner's hands-on, the stem knobs work like VirtualDJ's:
- **Layout `vdj` (default):** LOW = kicks, MID = melody (vocals + instruments + bass), HI = hats; all three fully left is silence.
- **Layout `raw`:** the plan 8 layout, still available.
- **Knob law:** turning a knob right raises its part, up to +6 dB.
- **Pads:** seven pad actions; overlapping pads multiply.

**Spec:** `docs/superpowers/specs/2026-11-08-stems-knob-layouts-design.md` (approved). It overrides the stems design and this plan's Global Constraints wherever they disagree.

**Architecture:**
- `StemSet` precomputes a **kicks** stem off the audio thread: a zero-phase low pass of rhythm, forward–backward, at the track's rate, 250 Hz. Hats are `rhythm − kicks` per frame, so the five parts sum to the mix exactly.
- The deck mixes five **parts** (vocals, instruments, bass, kicks, hats) with five ramped gains:
  `gain = knob_law(layout, knobs)[part] × pad_gains(flags)[part]`.
- Seven pad flags; `Stem` (the pad id) gains `Kicks`, `Melody` and `Hats`.

### Global Constraints (addendum)

- **Knob law (both layouts):** each knob gives its parts `eq_gain(p)`: 0 at 0, a squared law to 1 at 0.5, then up to +6 dB at 1. There is no isolation term.
  - `vdj`: vocals = instruments = bass = `eq_gain(mid)`, kicks = `eq_gain(low)`, hats = `eq_gain(high)`.
  - `raw`: vocals = `eq_gain(high)`, instruments = `eq_gain(mid)`, bass = `eq_gain(low)`, kicks = hats = 1.
- **Pads:** each part's pad gain is the product of the pads that cover it:
  - vocals = vocals × melody, instruments = instruments × melody, bass = bass × melody;
  - kicks = rhythm × kicks, hats = rhythm × hats.
- **Config:** `[stems] knobs = "vdj" | "raw"`, default `"vdj"`. Anything else is an error: `<file>: stems.knobs: <problem>`.
- **Anti-goals:** the plan's Global Constraints stand: centred knobs with every pad on are exactly the track in both layouts, and nothing clicks or allocates on the audio thread.

### Review Focus (addendum)

1. **Scratching or reversing with the split.** A muted kicks part stays absent in scratched, backspun and stretched output, and nothing glitches on a jump. Test: Task 9, `split_survives_scratch_and_keylock`.
2. **Stems arriving with LOW fully left in `vdj`.** The changeover crossfades with no click, in both layouts. Test: Task 9, `changeover_has_no_click` runs for both layouts.
3. **A 48 kHz track from the cache.** Kicks are computed at the track's own rate, so the split frequency is right. Test: Task 9, `kicks_split_low_frequencies` at 44.1 and 48 kHz.
4. **An existing `config.toml` without `knobs`.** It loads, with `vdj`; a typo is an error naming the key. Test: Task 10, `stems_knobs_config_parses_and_rejects`.
5. **The plan 8 knob tests silently passing on the old law.** `knob_law_matches_the_spec` is rewritten as a table for both layouts, and the old isolation cases are gone. Test: Task 9.
